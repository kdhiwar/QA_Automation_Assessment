Task 5: Strategy \& Leadership (Short Answers)



1.You are leading a team of 4 QA engineers. The sprint velocity is dropping due to flaky automation tests. How will you handle this situation?

Answer-

1\. Perform root cause analysis – check locator stability, environment, timing issues.

2\. Add intelligent waits and retry logic.

3\. Stabilize CI/CD environment (parallel runs, isolate tests).

4\. Implement review sessions and pair testing.

5\. Focus automation only on stable, high-value tests.

6\. Track stability metrics per sprint.

7\. Ownership \& visibility– Assign module ownership, monitor test reliability metrics.





2.During production release, you find 2 critical bugs reported by the client that were missed in QA. What’s your approach to fix gaps in process and testing?

Answer-

1\. Conduct root cause analysis with dev + QA.

2\. Strengthen regression and sanity coverage.

3\. Add requirement traceability matrix (RTM).

4\. Review test case design and peer review before execution.

5\. Add exploratory testing sessions before release.

6\. Implement automation smoke checks before deployment.

7.Shift-left testing – Involve QA early in story grooming and design discussions.

8.A continuous improvement loop ensuring test reliability, faster releases, and fewer production escapes.
